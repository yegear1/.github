# Contributing Guidelines

Thank you for your interest in contributing! These guidelines apply to public repositories maintained by [@yegear1](https://github.com/yegear1).

## Principles & Workflow

1. **Check Existing Discussions & Issues:**
   Before creating a new issue or PR, search existing open and closed issues to avoid duplicate reports.

2. **Reporting Bugs:**
   - Use the [Bug Report template](.github/ISSUE_TEMPLATE/bug_report.md).
   - Provide minimal reproducible examples, exact error output, and environment details (OS, runtime version).

3. **Feature Requests & Enhancements:**
   - Use the [Feature Request template](.github/ISSUE_TEMPLATE/feature_request.md).
   - Clearly describe the problem you are solving and why proposed changes benefit the tool.

4. **Pull Requests:**
   - Keep pull requests focused on a single change, fix, or feature.
   - Follow [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `chore:`, `refactor:`).
   - Ensure all automated unit and integration tests pass locally before opening the PR.
   - Follow clean git history: rebase onto main rather than creating messy merge commits when updating branches.
